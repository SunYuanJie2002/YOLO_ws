# 写作要求

## 风格
1. **不要按人群划分章节**（不要"给运营看"、"给开发看"这种标签）。
   按"具体的事情"组织目录，让所有人从同一个目录直达自己需要的章节。
2. **务实，不空话**。每个章节都要给出可以直接复制运行的命令或代码。
3. **多用表格**，少用大段散文。命令和参数说明用代码块。
4. **中文为主**，技术术语保留英文（如 EPC、Session、Docker）。
5. **不要用花哨的 emoji 装饰章节标题**，最多在表格里用 ✅/❌/⭐ 标记重点。
6. 文档总长度控制在 800~1500 行内，太长没人看。

## 必须包含的章节（按这个顺序）
1. 这个项目做什么（业务定位 + 简单类比）
2. 工作原理（ASCII 数据流图 + 启动到运行的步骤）
3. 快速开始（健康检查方式 + 本地运行 + 生产部署各一条命令）
4. 工程结构（目录树 + 各模块一句话职责表格）
5. 配置说明（配置文件全字段注释 + 环境变量覆盖 + Profile 切换）
6. REST 接口（如果有）/ 对外 API（每个接口：方法、路径、参数、响应、curl 示例、错误码）
7. {项目特有的核心功能章节}（比如"天线功率调节"、"任务调度"等）
8. 日志查看（容器日志 + 文件日志 + 关键词检索 + 关键日志含义说明）
9. 部署与运维（一键部署命令 + 常用 docker 命令 + 开机自启原理）
10. 改代码后怎么上线（Git 流程 + 哪些改动需要重建 vs 重启 vs 即时生效）
11. 二次开发（业务代码加在哪里 + 核心 API 速查）
12. 常见问题排查（每个问题：症状 + 原因 + 解决命令）
13. 领域基础知识（如果项目涉及非通用领域，比如 RFID / 区块链 / 量化）
14. 第三方 SDK / 库速查表（如果用了厂商 SDK 或复杂第三方库）

## 章节细节要求

### "快速开始"
- 必须能让新人在 5 分钟内验证项目是否在跑
- 给出健康检查的 URL 和预期返回
- 给出本地启动命令和生产部署命令各一条

### "配置说明"
- 把 yml/conf/env 全字段贴出来，每行加注释
- 写明哪些字段是必填、哪些有默认值
- 写明环境变量怎么覆盖配置（Docker 部署场景）

### "REST 接口"
- 每个接口必须有：HTTP 方法 + 路径 + 请求体示例 + 响应示例 + curl 命令
- 错误响应单独用表格列出常见错误码 + 消息

### "日志查看"（重点章节）
- 至少包含 5 个子节：
  a. 容器/进程日志的 6+ 种查看方式（实时、按行数、按时间、less 翻页等）
  b. 日志文件查看（按日期归档的情况）
  c. 关键词检索（统计、去重、grep 错误）
  d. 进容器内看日志
  e. 清空日志
- 最后单独列一节"关键日志含义"，把启动正常、连接成功、断开、异常等关键日志行贴出来加注释

### "常见问题排查"
- 每个问题用三段式：**症状** → **原因** → **解决（直接给命令）**
- 至少覆盖：服务起不来 / 连不上设备 / 日志没写出来 / 配置不生效 / 重启后服务没拉起来

### "工作原理"
- 必须画一张 ASCII 数据流图（外部设备 → 服务 → 输出）
- 然后用编号列表（1. 2. 3. ...）讲启动到运行的全过程
